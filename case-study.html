Portfolio/Case study

Production RAG chatbot

A campus RAG assistant built for 3,500+ people.

A production document assistant that retrieves from institutional sources, streams answers in real time, and stays inside the campus infrastructure.

Audience3,500+ people
RuntimeCampus servers
Model boundaryNo external LLM

01 / The problem

Campus knowledge was there. It just needed a useful front door.

I built the system from scratch as a capstone project. The goal was simple: let students and staff ask questions in plain language and get grounded answers from institutional documents, without sending that data to an external LLM service.

The hard part was making it dependable enough for real use. That meant retrieval had to handle both specific keywords and broader concepts, document updates could not require a full rebuild, and the interface had to show answers as they arrived.

02 / The system

A retrieval path with a few deliberate guardrails.

01 / IngestPDFs are tracked with SQLite metadata so only new or changed files are indexed.
02 / RetrieveFAISS dense search and BM25 keyword search each return useful context.
03 / FuseReciprocal Rank Fusion combines both result sets before generation.
04 / DeliverFastAPI streams tokens through Server-Sent Events to the campus interface.

03 / Engineering choices

The small decisions that made it feel production-ready.

Hybrid search

Dense vectors help with meaning. BM25 helps when users use the exact language found in campus documents. Combining both gave the assistant a more reliable retrieval foundation.

Incremental updates

SQLite-backed file metadata lets the ingestion job target only new or changed PDFs, which keeps ongoing maintenance practical.

Streaming UX

FastAPI Server-Sent Events deliver tokens as the answer is generated, so the interface feels responsive instead of making people wait behind a blank screen.

Failure handling

LLM circuit breakers, anti-hallucination prompts, and XSS sanitization add protection around the parts of an AI product that can otherwise become unpredictable.

04 / Outcome

A real deployment, not a one-off demo.

The assistant is live on campus infrastructure and serves 3,500+ students and staff.

This project brought together the work I enjoy most: retrieval quality, practical backend systems, local AI deployment, and an interface that gives people a clear path to an answer.
